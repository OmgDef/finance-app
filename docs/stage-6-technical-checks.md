## Клиенты предыдущего этапа

Использовали сохранённые тестовые сборки Release этапа 2 с отдельным идентификатором `com.tetafinance.app.acceptance` и номером сборки `1`. Обе содержали исходные Hermes-бандлы с адресом `https://192.168.139.211:18445`. На изолированной VM Caddy обслуживал этот адрес с прежним тестовым CA, принимал только маршруты мобильного API и передавал канонический `Host` порта `18743` текущему API. Контрольный запрос к административному маршруту вернул `404`.

Оба старых клиента прошли чистую активацию и повторный вход прежним PIN после холодного запуска. На каждом клиенте подтвердили email синтетического профиля. В MySQL для каждой учётной записи подтвердили одну активную регистрацию, один использованный код, одно событие `activation.used`, две сессии и ноль транзакций. Основные установки версии 4 сохранились на обоих эмуляторах.

## Сборки и воспроизведение

1. Подготовьте нативные каталоги через Expo prebuild и CocoaPods по [процедуре этапа 2](stage-2-technical-checks.md). Для локальной сборки задайте `EXPO_PUBLIC_API_ORIGIN` с HTTPS-адресом VM. Оба эмулятора должны видеть IP VM. Импортируйте CA Caddy в отдельный iOS Simulator через `xcrun simctl keychain "$IOS_SIMULATOR" add-root-cert "$VM_CA"`. Для Android подключите тестовый CA в сгенерированном проекте `android` через Network Security Configuration с одним доменом `192.168.139.211`, `includeSubdomains="false"` и `cleartextTrafficPermitted="false"`. В проверенных APK этот ресурс содержал CA этапа 6 и ранее установленный тестовый CA этапа 2, оба ограничены указанным IP. Сгенерированные проекты и CA остаются вне Git. Обычная сборка использует системное доверие к сертификатам.
2. Соберите из `apps/mobile` два Release для симулятора командой ниже. В сгенерированном `ios/TetaFinance/Info.plist` задайте `CFBundleVersion` как `$(CURRENT_PROJECT_VERSION)`, чтобы настройка Xcode попала в артефакт. В прогоне использовали нативный проект `TetaFinans`, Xcode 26.6, штатную подпись симулятора `adhoc` и сгенерированные тестовые Keychain entitlements этапа 2. Скопируйте первую сборку в отдельный каталог до запуска второй.

   ```bash
   xcodebuild -workspace ios/TetaFinance.xcworkspace -scheme TetaFinance \
     -configuration Release -sdk iphonesimulator \
     -destination 'generic/platform=iOS Simulator' \
     CURRENT_PROJECT_VERSION="$BUILD_VERSION" build
   ```

3. Задайте в сгенерированном `android/app/build.gradle` `versionCode` сначала 3, затем 4. Сохраните каждый APK отдельно. Соберите из `apps/mobile/android` с JDK 21 и одним тестовым ключом Gradle. В прогоне использовали SDK Build Tools 36.1.0 для проверки APK и архитектуру `arm64-v8a`. После сборок верните локальные нативные файлы в исходное состояние.

   ```bash
   ./gradlew :app:createBundleReleaseJsAndAssets --rerun -PreactNativeArchitectures=arm64-v8a
   ./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a
   ```

4. Остановите Metro и проверьте через `lsof -nP -iTCP:8081 -sTCP:LISTEN`, что порт свободен. Проверьте `adb -s "$ANDROID_EMULATOR" reverse --list`. Установите версию 3 на чистую синтетическую установку, активируйте её, запишите расход и переключите EN на RU. Завершите процесс приложения и установите версию 4 поверх с помощью `xcrun simctl install` или `adb install -r`. После холодного запуска проверьте русский экран разблокировки, вход прежним PIN, остаток и строку расхода. В прогоне сценарии выполнены через Maestro 2.6.0.

Обе версии имеют видимую версию `0.1.0` и идентификатор `com.tetafinance.app`. Установленные номера `3` и `4` подтверждены по `CFBundleVersion` и `dumpsys package`. `codesign --verify --strict` прошёл для обеих `.app`. `apksigner verify --print-certs` подтвердил один SHA-256 сертификата подписи обоих APK `fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c`.
